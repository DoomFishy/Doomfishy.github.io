Password Profiler

picoCTF | General Skills


Given userinfo.txt (Alice Johnson's personal information), hash.txt (SHA-1 Hash), and check_password.py (script to test passwords against the hash) Goal: using the information given to generate a custom password list to recover the original password by matching its hash.


I first manually combine the given information (name, nickname, birthday, partner, and child’s name), attempting to construct passwords that will match the hash. This is based on the prior knowledge that people use elements of personal information as passwords. After many combinations like alicejohnson07, charliealice1990, etc, I found no match. The bottleneck of manual combination was my own coverage as I could only think of a limited set of passwords, and since actual password constructions have special chars, random numbers, leet substitution, and other patterns that are difficult to do manually.


Reading the comments in check_password.py, I noticed the line. WORDLIST_FILE = "passwords.txt" # wordlist that was generated using CUPP This reveals that the challenge expects a dictionary that is generated by CUPP. After researching I learned that CUPP (Common User Passwords Profiler) automatically generates password lists based on personal information, special chars, random numbers, leet substitution, and other common patterns. This explains why my manual combinations had failed, as I was only covering a limited set of combinations, while CUPP’s generation logic covers many patterns of real passwords.


I cloned CUPP, ran it in interactive mode, and entered all the fields from userinfo.txt. During the CUPP, I selected “yes” to special chars, random numbers, and leet mode to maximize coverage. It then generated alice.txt, and ran it in check_password.py


The script hashed each password and compared it with the target hash SHA-1. When a match was output, it confirmed the password was correct, and the flag was obtained.
